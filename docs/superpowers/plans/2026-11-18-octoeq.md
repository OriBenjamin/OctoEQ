# OctoEQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An 8-band EQ Eight-style AU/VST3 plug-in for Ableton Live Intro on Apple Silicon, built by GitHub Actions.

**Architecture:** A JUCE-free DSP core (`Source/dsp/`) holds filter math and the 8-band engine and is unit-tested with a plain test executable. A JUCE `AudioProcessor` wraps it with parameters, oversampling and a spectrum FIFO; a JUCE editor draws the curve, nodes, spectrum and band strip. CI builds arm64 AU+VST3 on `macos-14` and uploads a zip.

**Tech Stack:** C++17, JUCE 8.0.x (CMake FetchContent), CMake ≥ 3.22, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-18-octoeq-design.md`

## Global Constraints
- Plug-in name `OctoEQ`; company `Octo`; manufacturer code `Octo`; plug-in code `Ocqe`; formats AU + VST3; `IS_SYNTH FALSE`, `NEEDS_MIDI_INPUT FALSE`.
- macOS build: `CMAKE_OSX_ARCHITECTURES=arm64`, deployment target 11.0.
- Frequency 10 Hz–22 kHz (log skew), gain ±15 dB, Q 0.1–18, Scale −200%..200%, Output ±24 dB.
- Types (index order): 0 LowCut12, 1 LowCut48, 2 LowShelf, 3 Bell, 4 Notch, 5 HighShelf, 6 HighCut12, 7 HighCut48.
- Defaults: band types [0,2,3,3,3,3,5,6]; enabled [off,on,on,on,on,on,on,off]; freqs [30,100,250,600,1500,4000,8000,18000]; gain 0; Q 0.71.
- Modes: 0 Stereo, 1 L/R, 2 M/S. Each of channel set A and B has its own 8 bands; Stereo uses set A on both channels.
- No Ableton names, colours copied from Ableton, or logos.

## Review Focus
- Frequency above Nyquist·0.49 (22 kHz at 44.1 kHz, or ×2 oversampling off at 32 kHz) → clamp, output stays finite. Test in Task 1.
- Host calls `prepareToPlay` again with a new rate/block size, or sends 0- or 1-sample blocks → no crash, no stale coefficients. Test in Task 2.
- Gain/freq jumps mid-playback → no NaN/inf and no step larger than smoothing allows. Test in Task 2.
- Mono (1-channel) bus → engine processes channel 0 with set A, no out-of-range access. Test in Task 2.
- Live set reopened → all parameters restored via state round-trip. Test in Task 3.

### Task 1: DSP filter core

**Files:** Create `CMakeLists.txt` (tests target only for now), `Source/dsp/Biquad.h`, `Source/dsp/Biquad.cpp`, `tests/dsp_tests.cpp`.

**Interfaces — Produces:**
- `enum class FilterType { LowCut12, LowCut48, LowShelf, Bell, Notch, HighShelf, HighCut12, HighCut48 };`
- `struct BiquadCoeffs { double b0,b1,b2,a1,a2; };` (normalized, a0 = 1)
- `BiquadCoeffs designBiquad(FilterType, double freq, double gainDb, double q, double sampleRate);` — RBJ cookbook; cut types use the stage for their slope (12 dB: one 2nd-order with given Q). Clamp freq to [10, 0.49·sr], Q to [0.1, 18].
- `int stagesFor(FilterType)` → 4 for *48, else 1. 48 dB stages use 8th-order Butterworth stage Qs {0.5098, 0.6013, 0.9000, 2.5629}; the last stage's Q is multiplied by (userQ / 0.7071) for resonance.
- `BiquadCoeffs designStage(FilterType, int stage, double freq, double gainDb, double q, double sr);`
- `double magnitudeDb(const BiquadCoeffs&, double freq, double sr);`
- `struct Biquad { BiquadCoeffs c; double z1=0,z2=0; float process(float); void reset(); };`

- [ ] **Step 1: Write failing tests** in `tests/dsp_tests.cpp`:
  - `bell_peak`: Bell 1 kHz +6 dB Q1 @48k → `magnitudeDb` at 1 kHz within 0.05 of 6.0; at 100 Hz within 0.5 of 0.
  - `lowshelf`: LowShelf 200 Hz +6 dB → 20 Hz ≈ 6.0 (±0.3), 10 kHz ≈ 0 (±0.3).
  - `lowcut12`: LowCut12 1 kHz Q 0.71 → 1 kHz ≈ −3 (±0.2), 250 Hz ≈ −24 (±1.5).
  - `lowcut48`: sum of 4 stages at 500 Hz for 1 kHz cutoff ≤ −45 dB; at 1 kHz ≈ −3 (±0.5).
  - `notch`: Notch 1 kHz → 1 kHz ≤ −40 dB.
  - `nyquist_clamp`: Bell 22 kHz +15 dB @44.1k; process 4096 samples of white noise through `Biquad`; all outputs finite.
- [ ] **Step 2:** `cmake -B build-tests -DOCTOEQ_TESTS_ONLY=ON && cmake --build build-tests && ./build-tests/octoeq_tests` → fails to compile/link.

### Task 2: 8-band engine

**Files:** Create `Source/dsp/EqEngine.h/.cpp`; extend `tests/dsp_tests.cpp`.

**Interfaces — Consumes:** Task 1. **Produces:**
- `struct BandSettings { bool enabled; FilterType type; float freq, gainDb, q; };`
- `class EqEngine { void prepare(double sr, int maxBlock); void setBand(int set /*0|1*/, int band /*0..7*/, const BandSettings&); void setMode(int mode); void setScale(float scale /*-2..2*/); void process(float* const* ch, int numCh, int numSamples); double responseDb(int set, double freq) const; double bandResponseDb(int set, int band, double freq) const; double sampleRate() const; };`
- Smoothing: freq/gain/Q per band linearly ramped over 20 ms; coefficients recomputed every 32 samples while ramping. Scale multiplies gain for Bell/Shelf types only.
- M/S: encode M=(L+R)/2, S=(L−R)/2, set A on M, set B on S, decode L=M+S, R=M−S.

- [ ] **Step 1: Failing tests:**
  - `defaults_flat`: default bands (Global Constraints) at gain 0 → `responseDb(0, f)` within 0.1 dB of 0 for f in {200, 1000, 5000}.
  - `scale`: band 3 Bell 1 kHz +6, scale −1.0 → response at 1 kHz ≈ −6 (±0.1); scale 0 → ≈ 0.
  - `lr_mode`: mode 1, set B band 3 +12 at 1 kHz; feed 1 kHz sine to both channels → channel 1 RMS / channel 0 RMS ≈ 12 dB (±0.5) after 0.5 s settle.
  - `ms_mode`: mode 2, set B gain only; identical L=R input → output equals input (±1e-4) after settle.
  - `mono_bus`: `process` with numCh 1 runs, outputs finite.
  - `reprepare_and_tiny_blocks`: prepare(44100,512), process; prepare(96000,1); process 1000 one-sample blocks and one 0-sample block → finite; `responseDb` at 1 kHz uses 96 kHz.
  - `param_jump`: steady 1 kHz sine, jump gain 0→+15 mid-block → all outputs finite, max |sample-to-sample delta| < 0.5.
- [ ] **Step 2:** Run tests → fail.
- [ ] **Step 3:** Implement `EqEngine`.
- [ ] **Step 4:** Run tests → all pass.
- [ ] **Step 5:** Commit `feat: 8-band EQ engine with stereo/LR/MS and smoothing`.

**Interfaces — Consumes:** Task 2. **Produces:**
- Parameter IDs: `b{set}{band}_on|type|freq|gain|q` with set ∈ {A,B}, band 1..8 (e.g. `bA3_gain`); `mode`, `edit` (0 A / 1 B), `scale`, `output`, `hiq`.
- `OctoEqProcessor : juce::AudioProcessor` with `juce::AudioProcessorValueTreeState apvts;`, `EqEngine& engine();`, `SpectrumFifo& spectrum();`

- Hi-Q: `juce::dsp::Oversampling<float>` 2×, IIR polyphase; switching calls `setLatencySamples` and re-prepares engine at the new rate on the audio thread's next block guard (atomic flag).
- Bus layouts: mono→mono and stereo→stereo.

### Task 4: Editor UI

**Files:** Create `Source/ui/EqDisplay.h/.cpp`, `Source/ui/BandStrip.h/.cpp`, `Source/PluginEditor.h/.cpp`.

**Interfaces — Consumes:** Task 3 parameter IDs, `engine().responseDb/bandResponseDb`, `spectrum().pull`.

- Editor 900×480, resizable 700×400..1600×900. Dark grey background, single accent colour per band (8 distinct hues).
- `EqDisplay` (top ~65%): log x 10 Hz–22 kHz, y ±15 dB (right axis labels), 30 Hz timer: pull spectrum → Hann + 4096 FFT (`juce::dsp::FFT` order 12) → smoothed dB fill (−90..0 mapped to the panel). Combined curve white 2 px; selected band's own curve filled in its colour at 25% alpha. Nodes = numbered circles (dimmed when off); drag x→freq, y→gain (cut/notch types: y→Q), wheel→Q, double-click→toggle, click selects band. Uses `ParameterAttachment`-style begin/endChangeGesture so Live records automation.
- `BandStrip` (bottom): 8 columns: on toggle, type combo (icons or short names: "LC12 LC48 LS Bell Notch HS HC12 HC48"), freq/gain/Q rotary knobs with value readouts; shows set A or B per `edit`.
- Global column on the right: Mode combo, Edit A/B toggle (hidden in Stereo), Scale knob, Output knob, Hi-Q toggle.
